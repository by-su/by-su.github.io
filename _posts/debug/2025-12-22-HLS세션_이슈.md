## 문제
VOD 시청 중 **일정 시간이 경과하면 재생이 중단되며 검은 화면으로 전환되는 장애**가 발생했다. 해당 이슈는 실사용자 환경에서 간헐적으로 재현되며, 시청 중 이탈을 유발하는 치명적인 사용자 경험 저하 문제였다.

## 원인 분석
### 재현
문제를 재현하기 위해 VOD를 직접 재생했고,  재생 도중 동일하게 검은 화면으로 전환되는 현상을 확인했다. 브라우저 콘솔 로그를 확인한 결과, VOD재생 중 HLS segment 요청에서 403 Forbidden 에러가 발생하고 있음을 확인했다.
![image](https://rootbly-images.s3.ap-northeast-2.amazonaws.com/notes/faf5cf90b2a63d84d507a40aac89324d.png)

클라이언트 측에서는 정상적으로 재생이 시작되었으나,  일정 시점 이후 일부 요청이 인증 실패로 거부되고 있었다.

### 서버 로그 분석
403 에러의 원인을 확인하기 위해 VOD 서버 로그를 분석했다.  VOD 서버는 총 5대의 서버로 구성되어 있었으며,  그중 2대의 서버에서 상반된 로그 패턴을 확인할 수 있었다.

### 정상 동작 서버 (219번)
![image](https://rootbly-images.s3.ap-northeast-2.amazonaws.com/notes/20d8676528df323e6cd186bb5a2774bf.png)
- 동일한 VOD 요청에 대해 HTTP 200 응답
- 정상적으로 VOD가 재생될 때의 로그 패턴

### 오류 발생 서버 (210번)
![image](https://rootbly-images.s3.ap-northeast-2.amazonaws.com/notes/c61f7cdcf2f77b4385ee5929066a5a00.png)
- 동일한 유형의 요청에 대해 HTTP 403 응답
- 인증 실패에 대한 명확한 에러 로그는 존재하지 않음

이를 통해 동일한 요청임에도 서버에 따라 응답 결과가 달라진다는 점을 확인했다.

![image](https://rootbly-images.s3.ap-northeast-2.amazonaws.com/notes/11db033f829c249bf47d99dcc2f80d6b.png)
도식도로 정리하면 다음과 같다.
1. VOD 요청
2. API 서버에서 `vod.fnup.com` 리턴
3. 첫 번째 HSL Segement요청은 1번 서버로 전달
4. N 번째 HSL Segement요청은 3번 서버로 전달 --> 인증 이슈 발생

## 가설 수립: 요청이 왜 다른 서버로 가는가?

시간 흐름에 따라 로그를 비교한 결과, VOD 재생 초기에는 219번 서버로 요청이 전달되다가,  일정 시간이 지난 후 동일한 VOD 요청이 210번 서버로 전달되면서 403 오류가 발생하는 패턴을 발견했다.
이로부터 본 문제는 단순한 인증 오류가 아니라 **재생 중 요청이 다른 서버로 분산되면서 발생하는 인증 이슈**일 가능성이 높다고 판단했다.


### DNS 구성 확인
요청이 서로 다른 서버로 전달되는 원인을 확인하기 위해 DNS 설정을 조사했다.
```
nslookup vod.fnup.com
Server:		168.126.63.1
Address:	168.126.63.1#53

Non-authoritative answer:
Name:	vod.fnup.com
Address: 180.68.207.221
Name:	vod.fnup.com
Address: 180.68.207.85
Name:	vod.fnup.com
Address: 180.68.207.58
Name:	vod.fnup.com
Address: 180.68.207.220
Name:	vod.fnup.com
Address: 180.68.207.210
```
결과, `vod.fnup.com` 도메인에 총 5개의 서버 IP가 매핑되어 있었으며, DNS 방식으로 요청이 분산되고 있음을 확인했다. 보안팀 확인 결과,  **동일 사용자에 대해서 약 1시간 주기로 DNS 응답이 변경되는 구조**로 운영되고 있었다. 대부분의 사용자가 VOD를 1시간 이상 연속 시청하지 않기 때문에, 해당 문제는 **특정 조건에서만 간헐적으로 발생한 것**으로 판단했다.

### 구조적 원인 분석을 위한 배경 지식: HLS 프로토콜

이 문제를 정확히 이해하기 위해,  VOD 서비스에서 사용 중인 HLS(HTTP Live Streaming) 프로토콜의 구조와 요청 특성을 분석했다.
#### HLS (HTTP Live Streaming)란?

HLS는 Apple이 제안한 **HTTP 기반 스트리밍 프로토콜**로,  
하나의 동영상 파일을 **여러 개의 짧은 미디어 조각(Segment)**으로 나누어 전송하는 방식이다.

##### HLS 기본 구성 요소

######  Master Playlist (`master.m3u8`)
- 해상도 / 비트레이트별 스트림 목록
- 네트워크 상황에 따라 클라이언트가 적절한 스트림 선택

######  Media Playlist (`index_xxx.m3u8`)
- 실제 영상 조각(`.ts`)들의 목록
- **재생 중 지속적으로 요청됨**

######  Media Segment (`.ts`)
- 실제 영상 데이터
- **수 초 단위로 분리된 다수의 HTTP 요청**

#####  HLS 재생 흐름
1. 클라이언트가 `master.m3u8` 요청
2. 선택된 `media.m3u8` 요청
3. **여러 개의 `.ts` 파일을 순차적으로 요청**
4. 재생 도중에도 **계속 새로운 segment 요청 발생**

### ### 장애와의 구조적 연결
HLS는 재생 중에도 다수의 HTTP 요청이 지속적으로 발생하는 구조이기 때문에,  **요청이 서로 다른 서버로 분산될 경우 서버 간 인증 상태가 일관되지 않으면  재생 도중 인증 실패로 인한 중단 문제가 발생할 수 있다.**

## 해결
### 임시 조치
근본적인 해결 이전에,  보안팀에 요청하여 DNS 연결 유지 시간을 3시간으로 증가시켜  동일 서버로 요청이 유지되도록 하여 장애 발생 빈도를 즉시 완화했다.

### 근본 해결
해결 방안으로 다음 두 가지 선택지가 있었다.

1. 인증 과정을 제거하는 방식
  - 구현은 가장 단순하지만, 인증 우회로 인한 콘텐츠 무단 접근 가능성이 있어 보안상 위험도가 높다고 판단하여 제외했다.
2.  HLS요청을 동일 서버로 고정하는 방식
  - 동일 사용자에 대해 하나의 서버로만 요청이 전달되도록 구조를 개선함으로써, 기존 인증 체계를 유지하면서 문제를 해결할 수 있었다.

최종적으로 2번 방안으로 다음과 같이 개선했다.
1. 각 VOD 서버에 대해 개별 도메인을 부여
2. 애플리케이션 레벨에서 VOD 목록 조회 시, 라운드 로빈 방식으로 각 VOD에 하나의 도메인을 할당
3. 사용자는 VOD 재생 시 단일 서버에 매핑된 하나의 도메인만 사용
